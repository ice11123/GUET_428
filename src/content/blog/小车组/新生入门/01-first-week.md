刚加入小车组时，你可能同时听到单片机、PWM、编码器、PID、循迹和通信等名词。不要急着把它们全部学完。第一周最重要的任务，是建立一张学习地图，并学会安全、可重复地做实验。

这篇文章不要求你有单片机经验，也不介绍某一辆具体小车。它先解决三个入门问题：学习顺序是什么、怎样判断一次实验有效、怎样留下别人能够复现的记录。

## 本篇目标

第一周不以“整车跑起来”为目标，而以建立可靠的实验习惯为目标。你要完成一次不接电机的可观察输出，读懂程序入口，并写下一份能够由同学复现的实验记录。

判断自己是否学会，不看记住了多少术语，而看能否把“预期现象—实际现象—证据—结论”说清楚。

## 先把目标想对

智能小车不是一个“会跑的玩具”，而是一个小型控制系统。它要完成四件事：感知环境、作出判断、驱动执行器，并利用反馈修正结果。

```mermaid
flowchart LR
  S[传感器<br/>看见状态] --> C[控制器<br/>计算下一步]
  C --> A[执行器<br/>产生动作]
  A --> W[小车与环境]
  W --> S
```

新生常见的误区，是一上来就追求“整车跑起来”。这样即使成功，也很难解释为什么成功；一旦失败，更不知道问题发生在哪一层。

正确顺序是：先验证一个输入或输出，再组合成一个功能，最后才做整车任务。

## 需要掌握的六块基础

| 模块 | 先学到什么程度 | 能做出的验证 |
| --- | --- | --- |
| 基础电学 | 电压、电流、功率、共地和电平 | 能用万用表确认供电是否合理 |
| C 语言 | 变量、条件、循环、函数、数组和结构体 | 能读懂并修改一个小函数 |
| 单片机 | GPIO、定时器、中断和串口的用途 | 能控制一个引脚并看到结果 |
| 执行器 | 电机、驱动器和 PWM 的关系 | 能让单个电机低速、短时转动 |
| 传感器 | 数字量、模拟量和计数信号 | 能读取并解释一个传感器值 |
| 控制方法 | 开环、反馈、误差和 PID | 能观察目标值与实际值的差异 |

这里的“掌握”不是背定义，而是能通过一次小实验说明它的作用。

## 第一周怎么安排

### 第 1 天：认识实验台

先找到电源、万用表、下载器、主控板、电机驱动板和急停或断电位置。确认谁负责设备、哪些接口不能带电插拔，以及实验结束后的整理规则。

当天不要接电机。先练习识别接口和阅读板上的丝印，例如 `3V3`、`5V`、`GND`、`VIN`、`TX`、`RX`。

### 第 2 天：练习测量

在学长或老师确认的低压电路上，用万用表测量电压和通断。每次测量前先说出：测什么量、表笔接在哪里、预计读数是多少。

如果说不出预计结果，先不要下表笔。预测是区分“测量”与“碰运气”的关键一步。

### 第 3 天：读懂最小程序

找到程序入口，观察初始化和主循环。暂时不要追进所有驱动文件，只回答三个问题：程序从哪里开始、哪段代码周期执行、怎样让系统安全停止。

### 第 4 天：验证一个输出

选择 LED、蜂鸣器或示波器可观察的 GPIO，不接电机。让它按照固定周期变化，并用现象或仪器确认程序确实在运行。

### 第 5 天：验证一个输入

选择按键或简单数字传感器，打印或显示其状态。分别记录正常值、触发值和断开连接后的表现。

### 第 6～7 天：整理一次完整记录

把接线、代码版本、操作步骤、预期结果、实际结果和异常写完整。请另一位同学只看记录复现实验；缺什么就补什么。

## 做实验的固定循环

以后无论调电机、编码器还是循迹，都可以重复下面的循环：

1. **提出问题**：这次只验证什么？
2. **作出预测**：正常情况下应该看到什么？
3. **控制变量**：一次只改一处接线、参数或代码。
4. **执行测量**：记录数值和现象，不只写“正常”或“不正常”。
5. **比较结果**：实际结果和预测差在哪里？
6. **保留证据**：保存代码版本、接线图、日志和结论。

> [!TIP]
> 调试不是不断尝试不同参数，而是不断排除不可能的原因。一次改很多地方，会让成功和失败都失去解释价值。

建议每次实验都保留下面六项信息：工程或提交版本、接线图、供电设置、本次唯一改动、测得的数据、下一步判断。只写“能跑”或“不能跑”，无法帮助下一位同学复现。

## 五条安全底线

- 改接线前先断电，确认电容和机械部件已经停止。
- 首次上电设置合理的限流，不直接使用最大电压或最大占空比。
- 电机实验先架空车轮，确保小车不会突然冲出实验台。
- 不确定接口电平时先查原理图或数据手册，不凭供电电压猜信号电平。
- 每个运动实验都要提前确定停止方式，停止功能必须比启动功能先验证。

## 怎样有效地向别人提问

“代码不行了”几乎无法帮助定位问题。一次有效提问至少应包含：

- 你想实现什么；
- 使用了哪些板卡和供电；
- 做了哪些接线与修改；
- 预期看到什么；
- 实际看到什么；
- 已经测量或排除了什么；
- 对应的代码版本和关键日志。

## 本篇总结

- 智能小车是由传感器、控制器、执行器和环境组成的控制系统，学习时应先验证单个环节，再逐步组合整车功能。
- 入组第一周的重点不是让整车立即跑起来，而是认识实验台、掌握基本测量，并建立“预测—实验—记录—复现”的调试方法。
- 每次实验都要控制变量并保留证据；涉及运动时，应先验证停机方式，再架空车轮进行低输出、短时间测试。
- 一份有效记录应包含目标、接线、代码版本、预期结果、实际现象和已经排除的问题，让其他同学能够复现实验。
